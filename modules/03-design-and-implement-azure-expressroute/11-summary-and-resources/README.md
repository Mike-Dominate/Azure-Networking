# Unit 11 — Summary and resources

**BlueHarbor chapter:** Enterprise-connectivity architecture review  
**Status:** NOT STARTED

## Architecture-board challenge

Explain without relying on the Portal:

- why BlueHarbor would choose ExpressRoute instead of relying only on VPN;
- what role VPN can still retain;
- circuit versus gateway;
- provider/service-key provisioning flow;
- Azure private and Microsoft peering;
- what BGP exchanges;
- what happens when a path/circuit/provider fails;
- why Global Reach exists;
- why FastPath exists;
- why private connectivity does not automatically mean encrypted traffic;
- how to troubleshoot a broken path from BlueHarbor edge to Azure workload.

## Module exit condition

The learner can design and troubleshoot the ExpressRoute path as a set of components and routing relationships rather than as one opaque Azure service.

The next BlueHarbor question is how to distribute traffic across healthy service endpoints. That leads into Module 4 — Load balance non-HTTP(S) traffic in Azure.
